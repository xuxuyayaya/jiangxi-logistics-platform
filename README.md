# 江西物流一张网 · 可运行演示平台

前端：原生JavaScript + 响应式CSS。后端：FastAPI。数据库：SQLite。浏览器通过后端API加载、创建和流转业务，不是纯静态页面。

## 启动

Python 3.12环境：

```
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

管理账号 `admin`，企业账号 `enterprise`，初始演示密码均为 `Demo@2026!`。部署前设置 `DEMO_ADMIN_PASSWORD` 和 `DEMO_ENTERPRISE_PASSWORD` 可替换初始账号密码。密码只在数据库首次初始化时读取，已有数据库需另行执行受控重置。

## Render部署

将目录内容推送到GitHub仓库，在Render新建Blueprint，选择仓库中的render.yaml。或创建Python Web Service，build命令为 `pip install -r requirements.txt`，start命令为 `uvicorn app:app --host 0.0.0.0 --port $PORT --proxy-headers`，健康检查 `/health`。

默认free计划不含持久盘，重启或重部署可能丢失新业务数据并恢复演示种子。保留业务数据需选择支持磁盘的付费实例并挂载 `/var/data`，设置 `DATA_DIR=/var/data`。本项目没有自行开通付费资源。后续多实例生产环境应迁移PostgreSQL。

高德地图：在Render环境设置 `AMAP_WEB_KEY`（Web端JS API Key）、`AMAP_SECURITY_CODE`（安全密钥），控制台配置实际onrender.com域名白名单。道路规划另设置 `AMAP_WEB_SERVICE_KEY`。JS Key为浏览器可见凭证；不得使用服务端Web服务密钥代替。

## 业务范围

包含管理/企业登录、隔离数据、运行看板、需求发布、参考报价、资源登记审核、联运估算、运单分段事件、模拟单据打印及PDF另存、政策演示自测、预警状态流转、接口模拟监控、工单处理、CSV导出、审计及53项PRD能力索引。

全部数据、政策、轨迹、价格、时效和单据为模拟。运输求解为演示成本估算，不是完整路网优化器。接口监控使用种子数据，没有实际连接政府、铁路、港口或企业生产系统。53项目录是需求索引，非全部已实现的生产功能。

公开部署的演示站请勿上传真实个人信息或商业数据。当前账号为展示用途，不具备生产账号管理、密码找回、第三方认证、精细字段授权、审计防篡改等完整生产保障。投产须单独实施对应PRD并完成安全与业务验收。

## API

`/docs`提供OpenAPI。核心接口：`/api/login`、`/api/me`、`/api/data/{kind}`、`/api/quotes`、`/api/plans`、`/api/export/{kind}`、`/api/audit`。Cookie使用HttpOnly、SameSite=Strict，HTTPS请求设置Secure；密码PBKDF2散列；状态变更校验版本和业务状态，操作留审计记录。

## V1.1：订单路线详情

运输需求及运单行均可点击进入独立详情页，地址示例 `/#order/waybills/JX-2026-0036`，支持刷新和浏览器前后导航。后端 `/api/routes/{kind}/{id}` 为每条记录生成对应路线、分段、节点事件、模拟载具、费用与单据清单；继承原记录访问权限。

页面提供左侧分段、中部地图、右侧位置和事件、下方六类详情页签。可点击分段聚焦、点击节点定位、拖动进度、播放或暂停模拟路线、切换回放速度、下载路线JSON、查看打印模拟运单、发起关联工单。默认使用OpenStreetMap底图（Leaflet，带来源署名）；配置高德后优先用高德，GPS坐标经其转换接口处理。底图服务失败自动退回可操作的SVG路线示意。外部服务仅用于底图，不向其传输订单主体或商业明细。

路线连接线与采样点为演示数据，不是路网导航结果或设备GPS实测轨迹；所有页面均明确标识。尚未产生真实交接文件的附件显示待补充，不伪造下载文件。

参考站已实际查看：shulian-ll 的横向导航、四类任务入口、白底卡片工作台和全程跟踪地图；wrc-szpt 的登录、横向业务导航及监管工作台。参考站部分数据面板存在加载或权限状态，未复制其账户、素材、真实数据或密钥。本站采用独立AI港口图及江西模拟数据。

## V1.2：真实道路规划与供需匹配

`AMAP_WEB_SERVICE_KEY` 用于服务端高德坐标转换和V5道路路线查询，Key不会发送浏览器；`AMAP_WEB_KEY`和`AMAP_SECURITY_CODE`用于地图展示。道路里程、时长、道路名与指引来自高德响应。铁路段接入 OpenRailRouting / OpenStreetMap 的已映射轨道线路，返回真实轨道几何，不含铁路班次、货运舱位或实时列车位置；轨道数据在部分地区可能缺失。海运路线服务暂不接入。地图只在两个已定位港口间显示虚线水上示意曲线，不代表真实航道，不提供海上距离、时效、船期或舱位。模拟GPS回放已停用，等待实际轨迹数据源。

`/api/matching/{demandId}`展示需求货量、时效、起讫和模式，及供方类型、可用/总容量、单位、硬约束、评分、适配范围和报价口径。运力吨位与仓储面积分开，多式联运的公路资源仅表示可匹配公路段。已关闭需求不再生成可承接推荐。跨省需求与运单样例覆盖南昌—武汉、南昌—上海、上海—南昌、九江—杭州、赣州—深圳、南京—南昌等省际方向；样例单据和货量仍为演示数据。

## V1.3：跨区域业务与专业工作台

需求可登记江西省内、跨省/全国及国际/跨境业务，起讫地支持自由输入；路线节点可按序录入，运输段可标注公路、铁路、水路等方式。未知地名先尝试高德地理编码；不能解析时不落到默认江西坐标、不画错误路线。公路段采用高德实路规划；铁路段显示已映射轨道参考；海运暂不接入，只有两个港口均定位时显示虚线水上示意。新增全国及国际模拟演示订单，均明确为模拟业务。

政策服务、预警协同、数据接入和服务工单使用各自的流程工作台，分别呈现申报与核验、分级处置、接口监控、工单流转；产品能力目录按业务域展开PRD场景、规则、字段、验收及规划边界。导航与字号按桌面工作台重新调整，卡片使用按业务主题绘制的轻量矢量插图。

## V1.5：产业场景与供需工作台
顶部导航按运行总览、运输协同、产业场景、资源服务、行业协同、平台管理分组。产业场景包含赣南脐橙、南丰蜜桔、南康家具、有色大宗、粮油农资、电子新能源，分别呈现流程、温控/包装/资质/单证条件，并可带入需求表单。具体温区由货主按品种、批次及采购标准填写。

路线只包含订单起讫点与明确填写的途经点；删除自动选取枢纽和模拟交接点。运输段序列与节点不一致时提示补充实际线路，不猜测换装站。路线导出为带来源、坐标系、查询时间的GeoJSON。供需工作台区分需求池、运力与仓储供给，展示方式、资质、容量和温控条件缺口，支持参考询报价；演示匹配不构成可订承运能力。

## V1.6：分段联运查询与实物照片
方案页参考辽宁项目的运输条件、发运/到达时间和结果比较流程，支持从已有需求载入、配置连续公路/铁路/水运段、逐段查询实际路径服务，并与公路直达基准比较。方案可保存为需求后进入分段地图。新增JX-MULTI-0001三段公铁联运样例；示例业务节点不代表已受理的铁路货运或班列任务。货运运价、班次、舱位和实际GPS/AIS仍须相应授权数据，不用固定系数代替真实报价。

六类产业场景改用本地保存的实物照片，来源、作者及许可记录在static/assets/scenes/credits.json并显示在卡片下。照片为同类实物参考，不表示江西产地、具体企业产品或实际货物凭证。

## 地图故障恢复与水运配置
订单地图使用本地坐标换算后绘制，取消逐批依赖高德在线坐标转换。SDK失败或底图超时切换本地Leaflet和OpenStreetMap备用底图，保留服务返回的实际几何并明确来源；支持重新加载、无线路分段点击和节点定位。备用底图不改变线路数据来源，瓦片失败也保留几何。

海运服务当前不要求配置SEAROUTES_API_KEY。港口间虚线只表示起讫关系，不代表实际海上航线；正式海运线路、航程和船期须待接入具备授权的数据服务后提供。高德地图与道路规划仍按各自Key配置。


## V1.7：场景业务工作台与需求驱动的联运求解
产业场景增加按角色组织的具体任务入口：脐橙与蜜桔突出采收批次、分选包装、采后暂存/温控、旺季车仓预约、销地线路、检疫与签收；南康家具突出进口原料入赣、大件尺寸/装柜、库位衔接和出口节点；有色与大宗突出长协批次、整车/整列/散货资源、专用线与过磅结算；粮油农资突出库存出库、仓容、城乡共配与回程货源；电子新能源突出JIT时窗、高值防护和电池分类。每项任务进入对应需求、资源、线路、政策或跟踪模块，场景模板不替用户虚构目的地、货物温区或承运能力。
联运查询按参考站点的需求字段组织：起讫、货类、重量、装载形式、发运/到达时间、预算和补充要求；可多选公路/铁路/水运比较路径，也可手动配置已确定的连续运输段。不会自动推断中转站，结果分别显示来源、路径里程/规划时长和待承运方确认的运价/班期/运力。海运暂以港口间虚线曲线表示。

## V1.8：实景图与物流资源运营工作台

登录、运行总览、产业专题和业务服务卡片改用与场景相符的真实摄影资料，移除原有 AI 风格港口插画与通用手绘 SVG 业务插画。图片均保留原作者、来源与许可链接；产业图片标注为同类实物参考，不暗示照片拍摄于江西具体企业。

“资源一张网”按运营工作台呈现：资源能力统计、运输/仓储快捷任务、可筛选目录、资源能力详情和高德资源节点地图。地图只显示登记坐标，不画虚构的运输连线；地图Key不可用时仍可查看资源目录和数据详情。资源库存和能力样例均明确标记为演示数据，吨位、面积分别统计。

## V1.9：政府与产业双视角驾驶舱

管理端总览增加政府侧运行监测、风险处置、政策服务和跨部门数据接入入口，统计值严格来自当前演示台账，不冒充官方货运量、物流成本或实时定位。企业端显示产业场景、撮合与公共服务入口。资源地图用不同标记区分仓储节点、运输资源和具备 GPS 坐标的在途车辆；目前示例运单没有真实 GPS，因此在途车辆位置数为零。总览已移除“全省资源”按钮，资源目录仍可从导航和地图侧栏进入。快捷操作改为清晰的线性图标。

## V2.0：政府与企业账号分开使用

管理账号进入政府侧演示首页与导航，聚焦物流运行监测、风险处置、跨部门数据接入、政策服务与产业运行观察；企业账号进入产业侧业务首页与导航，聚焦运输需求、联运方案、运单、资源和产业场景。双方仍可在权限允许范围内访问关联业务：政府侧可观察产业需求与资源，企业侧可查看公共政策服务。两侧首页不再混排。

## V2.1：统一账号驾驶舱

根据评审意见，当前演示恢复为一个统一账号入口，同时在同一驾驶舱清晰呈现政府协同与产业服务。政府侧覆盖运行监测、政策、预警、数据接入；产业侧覆盖需求、联运、运单和资源；六类江西产业场景在首页可见。资源目录照片按公路、铁路、港口水运、仓储等资源类别选择，避免用农产品照片表示冷链设施。V2.0 分账号布局不再作为当前交互方案。
